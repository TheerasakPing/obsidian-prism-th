# แนวทางการแปลและมาตรฐานภาษาไทย

## หลักการ

1. แปลความหมายและเจตนาการใช้งาน ไม่แปลคำต่อคำ
2. ใช้สำนวนสุภาพ กระชับ เป็นกลาง และสม่ำเสมอ
3. คงคำอังกฤษเมื่อเป็นชื่อเฉพาะหรือศัพท์ที่ผู้ใช้สายเทคนิคคุ้นเคย
4. ห้ามแปล code, command, API, model ID, file path, shortcut key หรือ config key
5. ไม่เพิ่มคำอธิบายที่เปลี่ยนความหมายหรือทำให้ข้อความยาวเกินจำเป็น

## รูปแบบข้อความ

- ปุ่ม: ใช้คำกริยาสั้น เช่น “บันทึก”, “ยกเลิก”, “ลองอีกครั้ง”
- สถานะ: ระบุสภาวะ เช่น “กำลังเชื่อมต่อ”, “เชื่อมต่อแล้ว”
- ข้อผิดพลาด: บอกสิ่งที่เกิดขึ้นและแนวทางแก้โดยไม่กล่าวโทษผู้ใช้
- Tooltip: อธิบายผลของการกระทำ ไม่ใช่เพียงทวนชื่อปุ่ม
- หน่วยและตัวเลข: รักษาหน่วย/รูปแบบที่ระบบคาดหวัง ห้ามแปล machine value

## Placeholders และ markup

ต้องคง placeholder ทุกตัวตรงตามต้นฉบับ เช่น:
- `{name}`
- `{{count}}`
- `%s` / `%d`
- ICU plural/select expressions
- HTML tags และ markdown links

ห้ามเปลี่ยนลำดับ argument หาก runtime ไม่รองรับ named placeholders

## การตรวจภาษาไทยบน UI

ตรวจอย่างน้อย:
- สระ/วรรณยุกต์ไม่ชนหรือถูกตัด
- line-height เหมาะสมกับฟอนต์ไทย
- ข้อความยาวไม่ทับ icon หรือ control
- tooltip/dialog ไม่ล้น viewport
- ปุ่มยังอ่านได้เมื่อแสดงภาษาไทย
- fallback font รองรับอักษรไทยจริง
- คัดลอกข้อความและค้นหาข้อความไทยได้ถูกต้อง
